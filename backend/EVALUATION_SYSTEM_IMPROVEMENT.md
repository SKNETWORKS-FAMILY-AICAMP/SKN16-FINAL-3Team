## 🔍 평가 시스템 문제점 분석

### 1. 제품 지식 검증 결과와 평가 결과의 불일치

#### 문제 상황
- **평가 결과**: "분할납부는 2개월부터 12개월까지 선택하실 수 있고" → 부정확
- **RAG 데이터**: "할부 (2~12개월): 연 5.9~15.0%" (CRD-CRE.jsonl 라인 11)
- **테스트 케이스**: "할부는 2개월에서 12개월까지 선택하실 수 있는데" → 정확한 정보로 평가된 적 있음

#### 근본 원인
1. **용어 불일치 문제**
   - "분할납부"와 "할부"는 실질적으로 같은 의미
   - 평가 모델이 용어 차이를 엄격하게 구분하여 부정확으로 판단했을 가능성
   - RAG 데이터에는 "할부"로만 명시되어 있어 "분할납부" 표현을 인식하지 못함

2. **제품 지식 검증 결과 반영 문제**
   - 평가 프롬프트에서 제품 지식 자동 검증 결과를 제공하지만
   - 평가 모델이 이 검증 결과를 충분히 신뢰하지 않거나
   - 검증 결과 자체가 "분할납부"를 "할부"로 매핑하지 못했을 수 있음

3. **평가 기준의 모호성**
   - 평가 프롬프트에서 "표현의 명확성은 전달력에서 평가"라고 했지만
   - "분할납부"와 "할부"의 의미 동일성 판단 기준이 명확하지 않음

### 1. LLM 프롬프트에 용어 동의어 예시 추가 ⭐ (가장 효과적)

**개선된 프롬프트**:

   - 숫자 예시: "연 2.5%" = "연간 2.5%" (정확함)

### 2. 코드 기반 용어 동의어 매핑 추가 (대안)

#### 문제
- "분할납부"와 "할부"는 같은 의미이지만, 평가 시스템이 이를 인식하지 못함

#### 개선 방안 (코드 변경)
프롬프트 개선만으로 부족하면, 코드 기반 매핑을 추가할 수 있습니다.

```python
# 제품 지식 서비스에 동의어 매핑 추가
TERM_SYNONYMS = {
    "할부": ["분할납부", "할부결제", "분할 결제"],
    "리볼빙": ["리볼빙 결제", "최소결제"],
    "일시불": ["일시불 결제", "전액결제"]
}

def normalize_term(term: str) -> str:
    """용어를 표준 형태로 정규화"""
    for standard, synonyms in TERM_SYNONYMS.items():
        if term in synonyms or standard in term:
            return standard
    return term
```

**코드 위치**: `backend/app/services/product_knowledge_service.py`

**단점**: 
- 코드 변경 필요
- 모든 동의어를 미리 정의해야 함
- 새로운 동의어 발견 시 코드 수정 필요
