# 📚 지식 평가 로직 가이드

## 🎯 개요

**지식 평가(Knowledge Evaluation)**는 시뮬레이션에서 직원이 제공한 제품 정보가 정확한지 자동으로 검증하는 시스템입니다.

### 왜 필요한가요?

- ✅ 직원이 잘못된 정보를 제공했는지 객관적으로 확인
- ✅ 정확한 정보를 제공했는지 자동으로 검증
- ✅ 피드백에 구체적인 오류 정보 포함

---

## 🔄 전체 프로세스 흐름

```
대화 기록
    ↓
[1단계] 사실 추출 (Fact Extraction)
    → 직원 발화에서 제품 정보 추출
    → 예: "정기예금 금리는 연 2.15%입니다"
    ↓
[2단계] 3단계 검증 (3-Step Verification)
    → Keyword Matching (키워드 매칭)
    → Semantic Similarity (의미 유사도)
    → LLM Verification (LLM 검증)
    ↓
[3단계] 정확도 계산
    → 정확한 정보 개수 / 전체 정보 개수
    → 예: 5개 중 4개 정확 = 80% 정확도
    ↓
[4단계] 점수 변환
    → 정확도 80% → 지식 점수 80점
    ↓
[5단계] 피드백 생성
    → 어떤 정보가 정확했는지/부정확했는지 설명
```

---

## 📋 1단계: 사실 추출 (Fact Extraction)

### 무엇을 하나요?

직원이 한 말에서 **제품 정보**를 찾아냅니다.

### 어떻게 찾나요?

#### 1. 제품 감지
- 키워드로 제품을 찾습니다
- 예: "정기예금" → `DEP-TIM` 제품 감지

#### 2. 정보 카테고리 추출
- 정규식 패턴으로 정보를 찾습니다
- 예: "금리", "한도", "가입금액" 등

### 예시

```
직원 발화: "정기예금 12개월 기본금리는 연 2.15%입니다. 최소 50만원부터 가입 가능합니다."

추출된 사실:
1. "연 2.15%" → 제품: DEP-TIM, 카테고리: 금리
2. "50만원부터" → 제품: DEP-TIM, 카테고리: 가입금액
```

---

## 🔍 2단계: 3단계 검증 (3-Step Verification)

각 사실이 정확한지 **3가지 방법**으로 검증합니다.

### 검증 방법 우선순위

```
1. Keyword Matching (키워드 매칭)
   ↓ (실패 시)
2. Semantic Similarity (의미 유사도)
   ↓ (복잡한 경우)
3. LLM Verification (LLM 검증)
```

---

### 1️⃣ Keyword Matching (키워드 매칭)

#### 무엇을 하나요?
- 제품 데이터에서 관련 정보를 찾습니다
- **구조화된 필드**를 활용합니다

#### 어떻게 찾나요?

**카테고리 기반 매칭** (최우선)
```
카테고리: "금리"
→ subsection_title에 "금리" 포함된 청크 우선 선택
→ 예: "기본 금리 (2025년 10월 28일 기준, 연이율)" 청크 매칭
```

**키워드 분리 매칭**
```
쿼리: "금리 연 2.15%"
→ 키워드 분리: ["금리", "2.15%", "2.15"]
→ 각 키워드가 청크에 포함되는지 확인
→ 50% 이상 매칭되면 관련 청크로 간주
```

#### 예시

```
주장: "금리 연 2.15%"
제품 데이터 청크: "기본 금리 ... 12개월 │ 2.15% │ 2.65%"
→ ✅ 매칭 성공! (카테고리 "금리" + 숫자 "2.15%" 일치)
```

---

### 2️⃣ Semantic Similarity (의미 유사도)

#### 무엇을 하나요?
- 주장과 정답의 **의미적 유사도**를 계산합니다
- 같은 의미지만 표현이 다른 경우도 인식합니다

#### 어떻게 계산하나요?

**임베딩 기반 (우선)**
```
1. 텍스트를 숫자 벡터로 변환 (임베딩)
   예: "연 2.15%" → [0.123, 0.456, ...] (1536차원 벡터)

2. 코사인 유사도 계산
   유사도 = 두 벡터의 각도 (0.0 ~ 1.0)
   
3. 임계값 비교
   - 임베딩: 0.75 이상 → 정확
   - SequenceMatcher: 0.7 이상 → 정확
```

**Fallback: SequenceMatcher**
- 임베딩 실패 시 문자 단위 유사도 계산

#### 예시

```
주장: "연 2.15%"
정답: "기본금리는 연이율 2.15%입니다"
→ 유사도: 0.95 (매우 유사) ✅
```

---

### 3️⃣ LLM Verification (LLM 검증)

#### 무엇을 하나요?
- 복잡한 주장을 **GPT-4o-mini**가 논리적으로 검증합니다
- 맥락과 논리를 고려합니다

#### 언제 사용하나요?

1. **복잡한 논리적 주장**
   ```
   예: "우대금리는 최대 0.5%p 추가됩니다"
   → 단순 키워드 매칭으로는 부족
   → LLM이 논리적으로 검증
   ```

2. **애매한 표현**
   ```
   예: "금리는 2.15~2.65% 범위입니다"
   → 범위 표현은 LLM이 더 정확히 판단
   ```

3. **맥락이 필요한 경우**
   ```
   예: "12개월 만기 기준으로는 2.15%입니다"
   → 조건부 표현은 LLM이 맥락 이해
   ```

#### LLM이 하는 일

```
입력:
- 주장: "연 2.15%"
- 정답 청크: "기본 금리 ... 12개월 │ 2.15% │ 2.65%"

LLM 분석:
"사용자 주장의 연 2.15% 금리는 제품 지식 베이스 정보에서 
12개월 계약기간의 기본금리와 일치합니다. 따라서 주장은 정확합니다."

결과: ✅ 정확
```

---

## 🔢 3단계: 정확도 계산

### 계산 방법

```
정확도 = (정확한 정보 개수) / (전체 정보 개수) × 100%

예시:
- 전체 정보: 5개
- 정확한 정보: 4개
- 부정확한 정보: 1개
→ 정확도 = 4/5 = 80%
```

### 검증 방법 통계

각 검증 방법이 몇 번 사용되었는지 기록합니다.

```
검증 방법: {
    "keyword": 2,  # 키워드 매칭 2번
    "semantic": 1,  # 의미 유사도 1번
    "llm": 2  # LLM 검증 2번
}
```

---

## 📊 4단계: 점수 변환

### 점수 계산 로직

```python
# 기본 점수 = 정확도 × 100
base_score = accuracy_rate × 100

# 예시:
# 정확도 80% → base_score = 80점
# 정확도 100% → base_score = 100점
```

### ⚠️ 중요: 이중 계산 방지

**이전 방식 (문제)**
```
정확도 80% → 기본 점수 80점
부정확한 정보 1개 → 추가로 15점 감점
→ 최종 점수: 80 - 15 = 65점 ❌ (이중 계산!)
```

**현재 방식 (개선)**
```
정확도 80% → 기본 점수 80점
→ 최종 점수: 80점 ✅ (정확도에 이미 반영됨)
```

**이유**: 정확도 계산 시 이미 오류가 반영되어 있으므로, 추가 감점은 이중 계산입니다.

## 🎯 5단계: 피드백 생성

### 피드백에 포함되는 정보

1. **정확도 요약**
   ```
   - 총 제품 정보 언급: 5개
   - 정확한 정보: 4개
   - 부정확한 정보: 1개
   - 정확도: 80%
   ```

2. **오류 상세 정보**
   ```
   ⚠️ 발견된 오류:
   - '연 3.5%' (실제: 연 2.15%)
   ```

3. **LLM Reasoning** (있는 경우)
   ```
   💡 검증 상세 분석:
   • '연 2.15%': 12개월 계약기간의 기본금리와 일치합니다
   • '50만원부터': 최소 가입금액이 50만원이라는 정보와 일치합니다
   ```

## 🔀 상황별 차이점

### 상품 데이터가 있는 경우

**적용 상황**: 수신 상담, 여신 상담, 카드 상담

**평가 방식**:
1. ✅ 제품 지식 자동 검증 수행
2. ✅ 정확도 기반 점수 계산
3. ✅ 구체적인 오류 정보 제공

**예시**:
```
상황: 수신 상담 (deposit)
→ DEP-TIM, DEP-FLX 등 제품 데이터 있음
→ 제품 검증 수행
→ 정확도 80% → 지식 점수 80점
```

---

### 상품 데이터가 없는 경우

**적용 상황**: 외환/송금 상담 (fx)

**평가 방식**:
1. ❌ 제품 검증 스킵
2. ✅ LLM이 일반 지식으로 평가
3. ✅ 절차 설명의 정확성 평가

**평가 기준**:
- ✅ 절차 설명의 정확성 (송금 절차, 수수료 안내 등)
- ✅ 일반적인 금융 지식의 정확성
- ✅ 금융 규정 및 정책 이해도
- ✅ 고객 질문에 대한 적절한 답변 제공

**예시**:
```
상황: 외환/송금 상담 (fx)
→ 제품 데이터 없음
→ 제품 검증 스킵
→ LLM이 "송금 절차 설명이 정확한가?" 평가
→ 지식 점수: LLM 판단 (일반 지식 기준)
```

## 🛠️ 기술적 세부사항

### 숫자 정확도 우선 처리

**중요**: 숫자가 포함된 경우, 숫자 정확도가 최우선입니다.

```python
# 숫자가 다르면 유사도가 높아도 부정확으로 판단
주장: "연 3.5%"
정답: "연 2.15%"
유사도: 0.9 (높음)
→ 하지만 숫자가 다름 (3.5 ≠ 2.15)
→ 결과: ❌ 부정확
```

**이유**: 금융 정보에서 숫자 오류는 심각한 문제이므로, 숫자가 다르면 무조건 부정확으로 판단합니다.

---

### 임베딩 캐싱

**성능 최적화**: 같은 텍스트는 임베딩을 캐시합니다.

```python
# 첫 번째 호출: 임베딩 계산
"연 2.15%" → [0.123, 0.456, ...] (계산)

# 두 번째 호출: 캐시에서 가져오기
"연 2.15%" → [0.123, 0.456, ...] (캐시)
```

---

### 검증 방법 선택 로직

```python
# 1. 카테고리 매칭 시도
if category_matches_subsection(category, subsection_title):
    return "category_subsection"  # 최고 점수

# 2. 전체 쿼리 포함 여부 확인
elif query in chunk_text:
    return "full_query"  # 높은 점수

# 3. 키워드 부분 매칭
elif keyword_match_ratio >= 0.5:
    return "partial_keyword"  # 중간 점수
```

## 📌 핵심 포인트 요약

### ✅ DO (해야 할 것)

1. **정확도 기반 점수 계산**
   - 정확도 80% → 지식 점수 80점

2. **숫자 정확도 우선**
   - 숫자가 다르면 무조건 부정확

3. **구조화된 필드 활용**
   - 카테고리 → subsection_title 매칭 우선

4. **LLM reasoning 활용**
   - 피드백에 구체적인 이유 포함

---

### ❌ DON'T (하지 말아야 할 것)

1. **이중 계산 금지**
   - 정확도에 이미 반영된 오류를 추가로 감점하지 않음

2. **불확실한 표현을 지식 점수에 반영하지 않음**
   - "~같아요", "~보이는데요" → 전달력(자신감) 평가에서 다룸

3. **상품 데이터 없는 경우 제품 검증 시도하지 않음**
   - 외환/송금 상담은 LLM 기반 평가만 수행

## ❓ 자주 묻는 질문 (FAQ)

### Q1: 왜 3단계 검증을 하나요?

**A**: 각 방법이 다른 상황에서 효과적입니다.
- **Keyword**: 빠르고 정확 (명확한 매칭)
- **Semantic**: 같은 의미 다른 표현 인식
- **LLM**: 복잡한 논리와 맥락 이해

---

### Q2: 정확도가 0%인데 점수가 50점인 이유는?

**A**: 제품 정보를 전혀 언급하지 않은 경우, 기본 점수 50점을 부여합니다.
- 이유: 정보 부족은 오류보다는 다른 문제이므로

---

### Q3: LLM 검증은 항상 사용하나요?

**A**: 네, 기본적으로 활성화되어 있습니다.
- `use_llm=True`로 설정되어 있음
- 복잡한 주장이나 애매한 경우에 특히 유용

---

### Q4: 외환/송금 상담은 어떻게 평가하나요?

**A**: 제품 검증 없이 LLM이 일반 지식으로 평가합니다.
- 절차 설명의 정확성
- 일반적인 금융 지식
- 규정 및 정책 이해도
