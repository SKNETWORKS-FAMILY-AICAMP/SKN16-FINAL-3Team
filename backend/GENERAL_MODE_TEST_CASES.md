# 일반 모드 시뮬레이션 테스트 케이스

## 📋 테스트 케이스 개요

일반 모드 시뮬레이션의 모든 기능과 시나리오를 검증하기 위한 포괄적인 테스트 케이스입니다.

---

## 1. 페르소나 조합 테스트

### 1.1 고객 타입별 기본 테스트

#### TC-001: 실용형 고객 (30대 직장인)
- **페르소나**: 실용형, 30대, 직장인
- **예상 행동**: 빠른 의사결정, 간결한 설명 선호, 효율성 중시
- **검증 포인트**:
  - 직원이 간결하고 명확하게 설명하는지
  - 불필요한 설명 없이 핵심 정보만 전달하는지
  - 빠른 처리 절차 안내가 이루어지는지
- **평가 역량**: 전달력(명확성), 기술(목표 달성도)

#### TC-002: 보수형 고객 (50대 은퇴자)
- **페르소나**: 보수형, 50대, 은퇴자
- **예상 행동**: 안정성 중시, 신중한 결정, 상세한 설명 요구
- **검증 포인트**:
  - 리스크와 안전성에 대한 설명이 충분한지
  - 예금자보호 한도 등 안전장치 설명 여부
  - 서두르지 않고 충분한 시간을 주는지
- **평가 역량**: 친절도(공감), 지식(정확성)

#### TC-003: 불만형 고객 (40대 자영업자)
- **페르소나**: 불만형, 40대, 자영업자
- **예상 행동**: 감정적 반응, 불만 표현, 해결책 요구
- **검증 포인트**:
  - 직원이 공감하고 이해하는 표현을 사용하는지
  - 부정 표현 회피 (negative_avoidance)
  - 해결책을 제시하고 안심시키는지
- **평가 역량**: 친절도(공감, 부정 표현 회피), 페르소나 정합도

#### TC-004: 긍정형 고객 (20대 학생)
- **페르소나**: 긍정형, 20대, 학생
- **예상 행동**: 친근한 대화, 긍정적 반응, 학습 의지
- **검증 포인트**:
  - 친근하고 긍정적인 톤 유지 여부
  - 교육적 설명 제공 여부
  - 고객의 긍정적 반응에 자연스럽게 대응하는지
- **평가 역량**: 친절도, 페르소나 정합도

#### TC-005: 급함형 고객 (30대 직장인)
- **페르소나**: 급함형, 30대, 직장인
- **예상 행동**: 시간 압박, 빠른 처리 요구, 간결한 설명 선호
- **검증 포인트**:
  - 빠른 처리 절차 안내 여부
  - 시간 절약 방법 제시 여부
  - 급함 표현에 적절히 대응하는지 (최대 1-2회만 허용)
- **평가 역량**: 기술(목표 달성도), 전달력(간결성)

### 1.2 나이대별 특성 테스트

#### TC-006: 20대 고객 (학생/직장인)
- **특징**: 금융 지식 낮음, 간단한 설명 필요
- **검증 포인트**:
  - 전문 용어 사용 시 설명 제공 여부
  - 용어 평이성 평가 (KB 권장용어 사전 준수)
  - 교육적 접근 여부

#### TC-007: 60대 이상 고객 (은퇴자)
- **특징**: 디지털 이해도 낮음, 안정성 중시
- **검증 포인트**:
  - 복잡한 디지털 절차 설명 시 단계별 안내
  - 오프라인 대안 제시 여부
  - 안전성 강조 여부

### 1.3 직업별 특성 테스트

#### TC-008: 외국인 고객
- **특징**: 언어 장벽, 문화적 차이
- **검증 포인트**:
  - 간단한 표현 사용 여부
  - 비언어적 소통 활용 여부
  - 문화적 차이 고려 여부

## 2. 상품 카테고리별 테스트

### 2.1 수신 (Deposit) 상품

#### TC-009: 정기예금 상담 (DEP-TIM)
- **상품 코드**: DEP-TIM
- **대화 유형**: A (상품 설명서 기반)
- **검증 포인트**:
  - 금리 정보 정확성 (기본금리, 우대금리)
  - 중도해지 시 이자 손실 설명
  - 예금자보호 한도 안내
  - 가입 절차 및 필요 서류
- **RAG 검증**:
  - 벡터 검색으로 금리 정보 검색 성공 여부
  - claim 검증 정확도 (예: "연 2.65%", "최대 연 2.65%")
  - 카테고리 매핑 정확성 (금리 → "금리" 카테고리)

#### TC-010: 자유적금 상담 (SAV-FRE)
- **상품 코드**: SAV-FRE
- **대화 유형**: A
- **검증 포인트**:
  - 자유납입 조건 설명
  - 우대금리 조건 (급여이체 등)
  - 세제 혜택 설명
  - 만기 및 중도해지 조건

#### TC-011: 입출금자유 상담 (DEP-FLX)
- **상품 코드**: DEP-FLX
- **대화 유형**: A
- **검증 포인트**:
  - 입출금 자유성 설명
  - 이자율 정보 (낮은 금리)
  - ATM 이용 수수료
  - 디지털 우대금리 조건

#### TC-012: MMDA 상담 (DEP-MMD)
- **상품 코드**: DEP-MMD
- **대화 유형**: A
- **검증 포인트**:
  - 최소 예치금액 조건
  - 차등 금리 체계
  - 입출금 제한 사항
  - 우대 조건

### 2.2 여신 (Loan) 상품

#### TC-013: 주택담보대출 상담 (LON-MTG)
- **상품 코드**: LON-MTG
- **대화 유형**: A
- **검증 포인트**:
  - LTV, DTI, DSR 규제 설명
  - 금리 체계 (기본금리, 우대금리)
  - 담보 인정 비율
  - 대출 한도 계산 방법
- **RAG 검증**:
  - 규제 정보 정확성 (70%, 60% 등)
  - 금리 범위 설명 정확성

#### TC-014: 신용대출 상담 (LON-UNS)
- **상품 코드**: LON-UNS
- **대화 유형**: A
- **검증 포인트**:
  - 신용평가 기준
  - 금리 범위 (연 5.6% ~ 9.0% 등)
  - 대출 한도
  - 필요 서류

#### TC-015: 예금담보대출 상담 (LON-DCL)
- **상품 코드**: LON-DCL
- **대화 유형**: A
- **검증 포인트**:
  - 담보 인정 비율 (95%)
  - 수취은행 제한
  - 초저금리 조건
  - 예금 잔액 유지 필요성

#### TC-016: 전세자금대출 상담 (LON-JNS)
- **상품 코드**: LON-JNS
- **대화 유형**: A
- **검증 포인트**:
  - 전세금 한도
  - 금리 조건
  - 필요 서류 (전세계약서 등)
  - 상환 방법

### 2.3 카드 상품

#### TC-017: 신용카드 상담 (CRD-CRE)
- **상품 코드**: CRD-CRE
- **대화 유형**: A
- **검증 포인트**:
  - 신용한도 안내
  - 연회비 정보
  - 포인트 적립률
  - 할인 혜택
- **RAG 검증**:
  - 소득공제율 정보 검색 (30%)
  - 세제 혜택 설명 정확성

#### TC-018: 체크카드 상담 (CRD-DEB)
- **상품 코드**: CRD-DEB
- **대화 유형**: A
- **검증 포인트**:
  - 계좌 연동 방식
  - 수수료 면제 조건
  - 소득공제 혜택 (30%)
  - 연간 공제 한도 (300만원)
- **RAG 검증**:
  - 소득공제율 claim 검증 (카테고리: "세금", "혜택")
  - "수수료" 카테고리로 잘못 매핑되지 않는지 확인

### 2.4 외환/송금 (Foreign Exchange)

#### TC-019: 환전 상담
- **대화 유형**: D (외환/송금)
- **has_product_data**: False
- **검증 포인트**:
  - 환율 정보 (현재 환율 안내)
  - 환전 수수료
  - 필요 서류 (신분증 등)
  - 환전 절차
- **RAG 검증**:
  - 상품 데이터 없으므로 RAG 검증 제외
  - 절차 지식 정확성만 평가

#### TC-020: 해외송금 상담
- **대화 유형**: D
- **has_product_data**: False
- **검증 포인트**:
  - 송금 절차 (1) 신청서 작성 2) 신분증 제시 3) 송금 완료)
  - 송금 수수료
  - 소요 시간
  - 필요 서류
- **평가 역량**: 지식(절차 지식), 기술(목표 달성도)

## 3. 대화 유형별 테스트

### 3.1 A 유형: 상품 설명서 기반 상담

#### TC-021: 특정 상품 상세 안내
- **조건**: `is_from_product_manual = True`, `product_code` 존재
- **검증 포인트**:
  - 상품 구조 설명 정확성 (70점)
  - 절차 지식 (15점)
  - 일반 금융 지식 (10점)
  - 카테고리별 특화 지식 (5점)
- **RAG 검증**: 필수 (has_product_data = True)

### 3.2 B 유형: 일반 상담 - 상품 관련

#### TC-022: 상품 비교 상담
- **조건**: `is_from_product_manual = False`, `product_code = None`, intent = 상품 관련
- **검증 포인트**:
  - 일반 상품 지식 정확성 (40점)
  - 절차 설명 (30점)
  - 일반 금융 지식 (20점)
  - 카테고리별 특화 지식 (10점)
- **RAG 검증**: 선택적 (상품 언급 시)

### 3.3 C 유형: 일반 상담 - 절차/규제 문의

#### TC-023: 계좌개설 절차 문의
- **조건**: intent = '계좌개설'
- **검증 포인트**:
  - 은행 업무 절차 지식 (50점)
  - 금융 규정 및 정책 이해도 (30점)
  - 일반적인 은행 창구 업무 지식 (20점)
- **RAG 검증**: 제외 (has_product_data = False 가능)

#### TC-024: 신분증 확인 절차 문의
- **조건**: intent = '신분증확인'
- **검증 포인트**:
  - 신분증 확인 절차 설명
  - 필요 서류 안내
  - 규정 준수 설명

### 3.4 D 유형: 외환/송금 상담

#### TC-025: 환전 절차 상담
- **조건**: situation_id.startswith('fx') 또는 intent = '환전문의'
- **검증 포인트**:
  - 절차 설명 (40점)
  - 환율/수수료 정보 (40점)
  - 외환 규제 이해도 (20점)
- **RAG 검증**: 제외 (has_product_data = False)

## 4. RAG 검증 기능 테스트

### 4.1 벡터 검색 테스트

#### TC-026: 벡터 검색 성공 케이스
- **조건**: 상품 데이터 존재, 유사한 청크 존재
- **검증 포인트**:
  - 유사도 임계값 이상 청크 검색 성공
  - 상품 코드 필터링 정확성
  - 카테고리 필터링 정확성 (subsection_title 기반)
  - top_k 결과 반환 (기본 5개)

#### TC-027: 벡터 검색 실패 케이스 (Fallback)
- **조건**: 초기 검색 결과 없음
- **검증 포인트**:
  - Fallback 검색 실행 (임계값 낮춤)
  - 카테고리별 동적 임계값 적용
  - 결과 없을 시 LLM 검증으로 전환

#### TC-028: UNKNOWN 상품 코드 처리
- **조건**: product_code = "UNKNOWN"
- **검증 포인트**:
  - 벡터 검색 건너뛰기
  - 문맥에서 상품 코드 추론 시도
  - 추론 실패 시 "unknown_product" 방법으로 처리

### 4.2 Claim 검증 테스트

#### TC-029: 숫자 정보 Claim 검증
- **예시**: "연 2.65%", "최대 연 2.65%까지 가능해요"
- **검증 포인트**:
  - 단위 무시 숫자 비교 (2.65% vs 연 2.65%)
  - 계산 예시 인식 ("기본 2.15% + 우대 0.5% = 2.65%")
  - 조건부 표현 인식 ("최대", "기준", "우대조건 충족 시")

#### TC-030: 범위 표현 Claim 검증
- **예시**: "5.6 ~ 9.0%", "리볼빙은 연 14%에서 17.9%"
- **검증 포인트**:
  - 여러 상품 범위 결합 인식 ("A나 B", "A와 B")
  - 개별 범위 확인 후 결합 범위 해석
  - Ground Truth에 개별 범위가 있으면 결합 범위 정확으로 판단

#### TC-031: 카테고리 매핑 정확성
- **예시**: "소득공제율 30%"
- **검증 포인트**:
  - CATEGORY_MAPPING 우선 사용 ("소득공제율" → ["세금", "혜택"])
  - LLM 추출 카테고리 무시 ("수수료" 추출해도 무시)
  - 확장된 카테고리로 벡터 검색 수행

#### TC-032: 청크 선택 로직
- **검증 포인트**:
  - 첫 번째 청크 우선 검증 (숫자 정확성 확인)
  - 숫자 불일치 시 top_k 청크 평가
  - 다중 점수 리랭킹 (유사도 40%, 숫자 매칭 30%, 키워드/섹션 30%)
  - subsection_title 매칭 우선순위

### 4.3 LLM 검증 테스트

#### TC-033: LLM Halucination 방지
- **검증 포인트**:
  - Ground Truth에 없는 정보 생성 금지
  - temperature = 0.0으로 일관성 보장
  - Ground Truth 기반 판단만 수행
  - 외부 지식 사용 금지

#### TC-034: 조건부 표현 해석
- **예시**: "12개월 기준", "우대조건 충족 시", "최대"
- **검증 포인트**:
  - 조건부 표현 인식 및 해석
  - full_utterance와 conversation_context 활용
  - 계산 예시 인식 ("기본 2.15% + 우대 0.5%")

## 5. 평가 역량별 테스트

### 5.1 지식 (Knowledge) 평가

#### TC-035: 상품 정보 정확성 (A, B 유형)
- **검증 포인트**:
  - 제품 지식 자동 검증 결과 활용
  - 정확한 정보만 "잘한 점"에 언급
  - 부정확한 정보만 "개선점"에 언급
  - 모순 금지 (같은 claim이 양쪽에 나타나면 안 됨)

#### TC-036: 절차 지식 정확성 (C, D 유형)
- **검증 포인트**:
  - 절차 설명의 정확성
  - 필요 서류 안내 정확성
  - 규제 이해도 정확성

### 5.2 기술 (Skill) 평가

#### TC-037: 상담 프로세스 준수
- **검증 포인트**:
  - 대화 흐름 자연스러움 (20점)
  - 목표 달성도 (30점)
  - 질문 활용 (25점)
  - 피드백 루프 (25점)

#### TC-038: 목표 달성도 평가
- **검증 포인트**:
  - 목표별 달성 여부 판단
  - 턴별 추적 정보 (달성 턴 번호, 증거 발화)
  - 목표 달성률 계산

### 5.3 친절도 (Kindness) 평가

#### TC-039: 부정 표현 회피
- **검증 포인트**:
  - "안 됩니다", "불가능합니다" 등 거부 표현 회피
  - 사실 서술은 부정 표현 아님 ("이자가 없고" 등)
  - 부정 표현 개선안은 긍정적 표현으로 변경

#### TC-040: 공감 표현
- **검증 포인트**:
  - 고객 감정 인식 및 공감 표현
  - 불만형 고객에 대한 공감
  - 긍정형 고객에 대한 친근한 대응

### 5.4 전달력 (Clarity + Confidence) 평가

#### TC-041: 용어 평이성
- **검증 포인트**:
  - KB 권장용어 사전 준수
  - 전문용어 사용 시 설명 제공
  - 일반적으로 알려진 용어는 설명 불필요 ("중도해지율", "이자소득세" 등)

#### TC-042: 숫자 표현 명확성
- **검증 포인트**:
  - 모든 숫자에 단위 명시 (100%: 15점)
  - 대부분 단위 명시 (80%+: 10점)
  - 일부 단위 명시 (50-80%: 5점)
  - 단위 명시 부족 (<50%: 0점)

#### TC-043: 문장 구조 및 간결성
- **검증 포인트**:
  - 평균 50자 이하 (30점)
  - 50-80자 (20점)
  - 80-120자 (10점)
  - 120자 이상 (5점)

### 5.5 페르소나 정합도 (Persona Fit) 평가

#### TC-044: 페르소나별 적절한 대응
- **검증 포인트**:
  - 실용형: 간결하고 효율적인 설명
  - 보수형: 안정성 강조, 신중한 안내
  - 불만형: 공감 및 해결책 제시
  - 긍정형: 친근하고 긍정적인 톤
  - 급함형: 빠른 처리, 시간 절약 방법
